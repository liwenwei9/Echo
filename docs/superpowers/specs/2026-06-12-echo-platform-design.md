# 回声（Echo）平台设计文档

> 2026-06-12 | 设计阶段 | 待实现

## 一、项目背景

基于对 Reddit、Snapchat、Threads 三款海外热门应用的深度分析，我们发现中国市场存在一个明确空白：**一个"内容质量 > 声音大小"的轻社交平台**。

### 海外三款应用分析摘要

| 应用 | 核心用户 | MAU | 核心价值 |
|------|---------|-----|---------|
| Reddit | 18-34岁，男性偏多，技术人员 | ~8.5亿 | 兴趣社区 + 投票民主化内容 |
| Snapchat | 13-24岁，Z世代均衡 | ~4.3亿 DAU | 阅后即焚 + AR + 真实社交 |
| Threads | 18-35岁，IG用户迁移 | ~3.2亿 | 极简短文 + IG社交流量 |

**三款共同的成功基因**：都解决了"在别人面前表达自己"的问题，只是表达的场域不同——Reddit面向同好圈，Snapchat面对真朋友，Threads面向关注者。

**中国的缺口**：微博是热搜/大V中心化，知乎算法崩坏，贴吧过气，豆瓣边缘化。普通人的声音没有机会被听见。

## 二、产品定位

- **产品名**：回声（Echo）
- **一句话定位**：不看粉丝数、只看内容好不好的轻社交平台，兴趣 + 地理位置双维度发现
- **目标用户**：25-35岁职场人，厌倦微博撕扯和朋友圈表演压力，想要有质量的讨论和本地连接
- **商业模式**：信息流广告 + 免费使用

## 三、核心机制

### 3.1 三条腿

| 腿 | 内容 |
|----|------|
| 内容民主算法 | 曝光量不与粉丝数挂钩，新人首帖有"新手流量池"，质量由互动深度加权 |
| 轻社交身份 | 不显示粉丝数，显示"回声指数"（综合内容质量和互动贡献），个人页是作品集 |
| 附近圈子 | 基于地理位置分层的兴趣小组，500m~5km 半径可选，线上讨论可落地到线下 |

### 3.2 产品价值观

- 内容质量 > 粉丝数量
- 真名/匿名混合，信任但不压迫
- 地理位置是发现工具，不是追踪工具
- 慢比快好，深度 > 碎片

## 四、附近圈子设计

### 4.1 地理粒度

| 层级 | 半径 | 内容 |
|------|------|------|
| 邻里圈 | 500m ~ 1km | 小区、街区话题：闲置交换、拼车、周边探店 |
| 片区圈 | 3km ~ 5km | 商圈/园区话题：午餐推荐、拼团、周末活动 |
| 城市圈 | 全城 | 展览、演出、政策讨论、同城面基 |

### 4.2 圈子类型

- **地点圈**：自动生成（小区、写字楼、商圈），用户可创建新地点
- **话题圈**：用户自建，绑定地理范围（如"望京夜跑群"）
- **活动圈**：限时48小时，围绕一个活动（如"周六三里屯市集"）

### 4.3 隐私保护（关键）

- 位置模糊化：只显示片区级别（"朝阳区望京"），不显示精确位置
- 距离显示控制：只显示"500m内"、"3km内"，不显示精确距离
- 离线隐身：可随时关闭地理可见性，进入"纯线上模式"
- 不暴露轨迹：切换半径不清除历史，不同时展示多个位置

## 五、去中心化推荐算法

### 5.1 曝光分配机制

- 质量算法池：60%（完全按内容互动深度排序）
- 地理位置池：30%（当前半径内邻居的内容）
- 关注流：10%（主动关注的人）

### 5.2 内容质量分（Echo Score）

| 维度 | 权重 | 说明 |
|------|------|------|
| 互动深度 | 40% | 评论字数 > 评论数 > 点赞数 |
| 停留时长 | 25% | 停留超过30秒计为深度阅读 |
| 收藏/分享 | 20% | 收藏权重最高 |
| 多样性惩罚 | 15% | 同一作者/同一话题短时间内不重复推荐 |

### 5.3 新手保护

- 首帖流量池：前3条帖子自动进入500人曝光池
- 冷启动期7天：内容获得1.5x质量分加权
- 回声加速：连续3条高质量内容触发2000人曝光

### 5.4 反流量垄断

- 粉丝数在所有信息流中隐藏
- 限流：单条内容24h最多曝光10万次
- 降权：标题党、情绪化煽动、重复内容自动降权

### 5.5 回声指数

```
回声指数 = 内容分×0.6 + 互动贡献分×0.3 + 社区贡献分×0.1
```

## 六、内容形态与互动设计

### 6.1 内容卡片类型

| 类型 | 格式 | 场景 |
|------|------|------|
| 观点 | 300字上限，纯文或配1图 | 行业看法、日常思考、热点讨论 |
| 故事 | 500字上限，多图(最多9张) | 生活分享、探店、本地事件 |
| 回声 | 引用他人帖子+自己观点(200字) | 延续讨论，赞同/反驳 |
| 提问 | 标题+可选补充(200字) | 求助、征集意见、本地问路 |

### 6.2 互动三按钮

- **赞同**：我同意你的观点
- **感谢**：这个内容对我有帮助
- **不认同**：需附上至少10字理由，不显示数量，只反馈给算法

不做传统转发，只做"回声"（引用式转发）。

### 6.3 评论机制

- 评论也是内容，同样参与质量分计算
- 默认按"最有价值"排序，可切换时间序
- 短于5字且无信息量的评论不进入价值排序
- 楼主可置顶一条有价值的评论

### 6.4 每日话题

- 每天5个话题（3个全国+2个本地）
- 编辑+算法共同筛选
- 话题帖额外10%曝光加权
- 第二天归档为话题档案

### 6.5 信息流

三标签切换：[发现] [附近] [关注]，默认进入发现页（质量算法池）。

## 七、技术架构

### 7.1 系统架构

```
客户端: iOS (Swift) / Android (Kotlin) / Web PWA (Next.js)
         ↓ REST + WebSocket
网关:    Nginx/Kong
         ↓
API层:   FastAPI (Python)
         ├── 用户服务
         ├── 内容服务
         ├── 推荐服务
         ├── 圈子服务
         ├── 位置服务
         └── 通知服务
         ↓
数据层:  PostgreSQL / Redis / Elasticsearch / S3-OSS / Kafka
```

### 7.2 核心数据模型

- **User**：id, nickname, avatar, bio, verified_identity, echo_score, location_privacy, current_radius
- **Post**：id, user_id, type(观点/故事/回声/提问), content, media_urls, topic_tags, location_point, quality_score, exposure_count, max_exposure
- **Circle**：id, name, type(地点/话题/活动), center_point, radius_meters, owner_id, member_count, activity_score, expires_at
- **Interaction**：id, user_id, post_id, type(赞同/感谢/不认同/回声/评论), content, quality_weight
- **CheckIn**：id, user_id, circle_id, post_id, location_point, is_verified

### 7.3 推荐流水线

```
新帖发布 → 内容预处理（去重/敏感词/质量预估）
         → 新手流量池
         → 实时互动数据采集
         → 质量分计算（每5分钟更新）
         → 曝光分配决策
         → 多样性过滤+降权检查
         → 推送至用户信息流
```

## 八、技术选型

| 层 | 技术 | 理由 |
|----|------|------|
| 移动端 | Swift/Kotlin 原生 | 性能最佳，地理位置功能原生API更稳定 |
| Web端 | Next.js PWA | 低开发成本快速验证，PWA可暂代App |
| 后端API | Python FastAPI | 推荐算法与Python生态天然契合 |
| 数据库 | PostgreSQL + PostGIS | 地理空间查询原生支持 |
| 缓存 | Redis | 信息流缓存、地理位置热点 |
| 搜索 | Elasticsearch | 全文搜索+话题发现 |
| 消息队列 | Kafka | 异步处理互动数据、质量分计算 |
| 存储 | S3/阿里云OSS | 图片等媒体资源 |
| 推荐 | 自研+scikit-learn | MVP阶段用Python生态，后续可迁移到Go |

## 十、风险与对策

| 风险 | 对策 |
|------|------|
| 冷启动没有内容 | 种子用户邀请制，编辑手动填充，每日话题引导 |
| 地理隐私恐慌 | 模糊化优先，隐私设置默认最严格 |
| 内容审核压力 | 敏感词自动过滤+用户举报+人工审核三级机制 |
| 增长太慢 | 第一期聚焦一线城市互联网/科技园区，单点打穿 |
| 大V/营销号入侵 | 算法降权+限流+反作弊，保护内容民主基因 |
